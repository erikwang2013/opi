01 / MEET OPI

A keycap,
taken seriously.

Opi is the project pet of opi and a keycap sprite. It looks like a single key on a keyboard — because an input method should be nothing more than that.

Its body is a keycap, its mouth the letter O (Open), its antenna the pinyin tone mark ˉ, its side legend opi. The ripples below spread only on this machine. None of this is decoration: it is how the project thinks about input.

  • Open: open engine, open dictionaries, transparent and auditable.
  • People: designed for everyone; input is never used for anything else.
  • Input: back to the essence — just get the characters right.
  • No cloud sync, accounts, ads or telemetry.

02 / FEATURES

Small things,
done right.

No pop-ups, no accounts, no "you may also like". One clear input path and a deliberately small toolkit. Cloud sync is decided against; the README records the boundaries.

One engine, six native clients

A Rust core with native shells: Android IME, fcitx5, Windows TSF, macOS / iOS keyboard extensions and HarmonyOS N-API. The same dictionaries and keycodes; each UI is its own.

RustC ABIAndroidWindowsLinuxmacOSiOSHarmonyOS

Android (emulator), Windows (real device) and Linux (container / local) have runtime verification. iOS, macOS and HarmonyOS have buildable artifacts but no real-device acceptance.

Offline first, privacy you can check

Input, candidates and user words stay on the device. No login, cloud sync or telemetry; the only network access fetches version.json and carries no input data.

0 cloudNo accountNo telemetryUpdate check only

Chinese input, one pipeline

Pinyin / Simplified–Traditional / Shuangpin / Wubi / stroke, with 26 / 9 / 14-key layouts; symbol hints sit above letters and long-press or swipe-up reveals case and symbols, while the punctuation column scrolls and can be customised. Two independent custom-phrase sets (Android / desktop / macOS settings): the Chinese set triggers only on the Chinese keyboard and the English set only on the English keyboard, by exact match; on mobile an opening bracket now inserts its closing partner with the caret between. Composing pinyin stays visible and auto-segments; idioms, xiehouyu and 3-to-multi-character combinations are recognized as whole phrases. Traditional support varies by client.

PinyinShuangpinWubiStroke9 / 14 / 26 keysCN / EN phrasesphrase composition

A living dictionary

The main Simplified and Traditional dictionaries are separate tracks; Kangxi, modern Traditional phrases and common vocabulary keep merging in. Dictionary changes have gates and regression tests. Optional 200k-entry CustomPinyinDictionary / rime-wanxiang packs can be imported.

Opi and expressions

Twelve animated Opi stickers, 689 OpenMoji expressions and 390 kaomoji. Opi stickers carry an Opi label and never collide with emoji names.

12 forms689 emoji390 kaomoji

A restrained desktop experience

The Linux / Windows status bar appears only while OPI is active; Windows upgrades in place without signing out (new apps pick it up, already-open apps need a restart); Android / HarmonyOS gears open an in-keyboard settings page. Thirty skins share one list: 11 solid colors (Fresh by default) change the palette only, while 19 animated illustrated skins each carry their own palette and recolor keys, candidates and the status bar as the artwork changes. On mobile the art sits behind the keys, while on desktop characters spill out from the status-bar edges. Every About page can check for updates and download full or hot packages in-app with progress and verification.

03 / TIMELINE

From one keycap
to six platforms.

Not a straight line: engine, dictionaries, platform shells and the expression system grew together. These are a few moments worth keeping.

  1. 2026.11.01v1.29.0

    Skins across every page, LAN clipboard

    Dynamic artwork now covers settings, skin/mode/symbol/emoji/about/tiled-candidate pages as well as the keyboard, with readable scrims. Corrected/jianpin/fuzzy candidates append matching symbols or kaomoji. New cross-device clipboard: off by default, 6-digit SAS pairing, Noise-encrypted plain text (≤256 KiB) on the same LAN, no cloud; Android/Windows/Linux listen automatically, macOS polls, iOS/HarmonyOS degrade to keyboard-visible prompts. One-click stop.

  2. 2026.10.31v1.28.3

    Keys wear the artwork

    Dynamic skins no longer just adjust key transparency: Android, iOS and HarmonyOS keys now use the theme's illustration crop (keycap-<id>.png, aspect-filled — iOS no longer stretches it), while the full scene stays visible between keys. The desktop / Windows candidate window draws the full scene under a 52% theme tint. Solid skins keep their opaque keys.

  3. 2026.10.31v1.28.2

    Artwork on the keys

    Dynamic skins no longer show only colours and overflow art: Android key plates are 68% opaque with a 16% key-area scrim; iOS key plates 68% and key area 20%; HarmonyOS keyBg 72% and scrim 18%; the desktop status bar draws the scene inside the bar with translucent bar and buttons. Solid skins are unchanged; key labels get a shadow for contrast.

  4. 2026.10.31v1.28.1

    MSI smoke fixed

    Windows Server Core has no TSF, so the MSI's OpRegisterTsf rolls back by design (1603). The container smoke now accepts only that known rollback (action Return value 3), keeps all other failures red, and is a real gate again. Functionally identical to 1.28.0; only the version, CI and docs changed.

  5. 2026.10.31v1.28.0

    Redrawn illustrations, all five clients

    All 19 scenes were redrawn with clear outlines, layered scenery, complete flower vines and branches, rooted stems and grounded props. New shared high-resolution assets live in shared/scene/art. Android and desktop render live; iOS, macOS and HarmonyOS show the same assets. Every client now lists the same 11 solid + 19 animated skins, Fresh by default. Also new: symbol-name input (Chinese mode zuokuohao→（, jiantou→→, kaixin→kaomoji; English mode leftbracket→[, arrow→→), link labels without raw URLs on About pages, and verified local packages reused before downloading.

  6. 2026.10.31v1.27.1

    30 skins: solid + animated

    Dynamic themes are now the skins themselves: the separate color-skin and background pickers are gone, and the original 11 solid colors are back in the same list (Fresh by default). Solid skins only change the palette; each of the 19 animated themes carries its own palette and changes artwork together with the key, candidate and status-bar colors. The desktop status-bar logo cycles solids then themes, and restored configs derive the palette from the theme.

  7. 2026.10.31v1.27.0

    19 animated skins & in-app updates

    Nineteen animated illustrated skins each ship their own palette: picking one changes the artwork and the key, candidate and status-bar colors together. On mobile they sit behind the keys; on desktop status-bar characters spill out in staggered islands (transparent window plus X11 input pass-through), with outlined key plates for contrast. The desktop and Android About pages now download full and hot packages in the background with progress, cancel, SHA-256 and size verification instead of opening a browser; Android DownloadManager keeps downloading after leaving the app, and a Linux hot-update zip is published.

  8. 2026.10.30v1.26.6

    Emoji categories & association fixes

    Emoji and kaomoji categories on Android, iOS and desktop now render exactly the selected group, fixing the previous-group offset; empty categories show a hint and re-tapping returns to the top. Android's Smart association switch applies immediately and clears hidden suggestions. Android shares one emoji fetch/glyph probe and iOS caches filtered emoji data to cut repeated work.

  9. 2026.10.29v1.26.5

    Cross-platform consistency

    Cross-platform consistency and performance: iOS/HarmonyOS now persist user words; language and Traditional switches preserve the in-progress buffer; macOS gains bracket pairing; HarmonyOS gets pending-text support. Android moves engine loading and learning writes off the main thread and reads candidate annotations on demand. TSF drains selected candidates on focus, keeps text across mode switches, handles deactivation and layout-aware hotkeys. Linux gains candidate paging; dictionaries are rebuilt with fixed-capacity frequency slots; a Cangjie data stage (79,261 entries, no UI yet) lands; version and CI gates are hardened.

  10. 2026.10.28v1.26.4

    Association switch & privacy

    A Smart association switch on all six platforms, off by default; fcitx5 suggestions are numbered and selectable by number, with PageUp/PageDown and -/= paging; TSF hides suggestions when the switch is off; Chinese/English privacy pages go live and every About page links to them.

  11. 2026.10.28v1.26.3

    Smart association

    After committing, suggest common continuations from prefixes and a compact semantic table across all six platforms; tap to keep chaining (TSF commits on the next key press); any key or caret move dismisses. Site gains a 404 page.

  12. 2026.10.27v1.26.2

    Readings no longer expose key digits; the 14-key layout gains multi-character composition and sentences; ranking aligned with the 26-key layout; iOS pet-strip and system top-edge fixes.

    Windows interactive upgrades restart the user shell; function and special keys pass through; IME switch releases the status bar; Android / HarmonyOS gear opens an in-keyboard settings page.

  20. 2026.10.26v1.26.0

    Brackets, smarter learning

    Bracket auto-pairing on Android/iOS/HarmonyOS: an opening bracket inserts its closing partner with the caret between, an expected closing symbol is skipped, and an empty pair deletes with one backspace. Smarter learning: space-accept weighs +1 and explicit selection +2, changing the choice for the same input undoes the previous vote, English candidates read learned frequency, and fcitx5/macOS persist user words with debounce. Mobile candidate windows grow from 64 to 512 so deep exact matches such as 壹 are reachable, and optional CustomPinyinDictionary / rime-wanxiang converters and licensing docs are included.

  21. 2026.10.26v1.25.7

    First-key spike

    26-key finite windows now select tier-by-tier from the full pool and materialise only the leading segment (3.5–6ms measured in a desktop release build); 9-key single keys skip the pointless fallback scan; finite windows are exact prefixes of the unlimited list, fixing display/commit mismatches.

  22. 2026.10.26v1.25.6

    Segmented queries and hot paths

    9-key segmented queries use range enumeration instead of a full-table scan (882ms to 1.1ms); HarmonyOS drops the duplicate pageCount; iOS reuses the dictionary; Android validates optional dictionaries once and caches backspace selection; Linux no longer re-ranks on Shift.

  23. 2026.10.25v1.25.1

    Phrase hot-load and keyboard polish

    Custom phrases are off by default and hot-load on enable; mobile popups are one horizontal row and the 26/14-key “英/中” key switches in one tap; the 9-key punctuation column narrows, the right column gains 0 and space moves to the bottom-row centre; Windows gets a small status-bar radius; the iOS pet strip fills the width and the top rounded background is themed.

  24. 2026.10.24v1.25.0

    CN/EN phrases and keyboard redesign

    Two fully independent custom-phrase sets land in Android / desktop / macOS settings. The mobile 9/14/26-key and Wubi keyboards are redesigned against the reference layouts: ordinal badges, symbol hints, long-press/swipe-up popups, a scrollable punctuation column and custom symbols. The 9-key pinyin row no longer shows raw key digits (468 fix, matched on iOS and HarmonyOS).

  25. 2026.10.23v1.24.5

    iOS crash fix and English keyboard

    The Auto Layout crash when tapping 繁/123/English on the 9-key face is fixed from a real .ips (reading-column constraints are deactivated before key rows are torn down); a random multi-form pet strip now sits at the top. The mobile English keyboard shrinks the space bar, moves , . before it, swaps ⌫/↵ and sends !?# straight to the English symbol category.

  26. 2026.10.23v1.24.4

    Mobile 9-key composition and full pinyin row

    Digit-space composition now covers three-, four- and longer words (厌蠢症, 样样通). The pinyin row no longer pads pending keys with dots; uncovered keys are filled with key-cap letters and the row scrolls horizontally. iOS inserts numeric-layer digits directly, loads dictionaries lazily and rebuilds keys once when switching to English; Android keyboard panels gain an update check.

  27. 2026.10.23v1.24.3

    iOS 9-key and stability

    iOS 9-key 繁/123/English stay inside opi; 🌐 short-press cycles languages, long-press switches the system keyboard; old key rows are released before rebuild with logging. The Windows white-screen fix carries over from 1.24.2 and is now verified on a real device.

04 / TWELVE FORMS

Twelve Opis,
twelve moods.

It lives beyond the settings page: candidate bar, empty states, launcher icon, status bar. Click any card to see its mood.

All twelve forms are original opi assets, not built-in emoji. The IME inserts them as animated GIF / PNG stickers with an Opi label; hosts that reject images fall back to a text label.
