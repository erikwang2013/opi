# 括号配对：三端唯一规范表

自动配对在 Android / iOS / 鸿蒙三端各有一份实现，**键值表与行为契约以本文件为准**。
改表必须三端一起改；每端的源码头注都指回本文件。

| 开 | 闭 |
|---|---|
| `(` | `)` |
| `[` | `]` |
| `{` | `}` |
| `（` | `）` |
| `【` | `】` |
| `《` | `》` |
| `「` | `」` |
| `『` | `』` |
| `“` | `”` |
| `‘` | `’` |

实现（逐项镜像上表）：

- Android：`android/app/src/main/kotlin/xyz/erik/opi/ime/BracketPairing.kt`
- iOS：`ios/BracketPairing.swift`
- 鸿蒙：`harmony/entry/src/main/ets/InputMethodExtensionAbility/BracketPairing.ets`

行为契约：

1. 用户敲出的文本**整体恰好等于**某个开符号时：插入「开+闭」，光标停在两者之间。
2. 记住这一对（及插入时两侧各最多 8 个字符的上下文）。只有**仍在同一位置、上下文未变**
   的那一对才参与后续动作 —— 用户自己原有的括号、或光标已离开的旧配对都不动。
3. 下一个敲出的字符整体恰好是配对的闭符号且仍在配对中间：**不插入**，光标右移一格
   （吃掉已存在的闭符号）。
4. 光标恰在空配对中间按退格：把两个字符一起删掉。
5. 其它任何输入/候选上屏都会结束跟踪：经配对入口的输入都清空跟踪，其余直提路径
   （候选上屏、空格等）由「上下文回读失配」兜底；英文模式、密码/安全输入框不做配对。
6. 只处理本表；ASCII 开只配 ASCII 闭，全角/中文开只配对应的中文闭。
