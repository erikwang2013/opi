# Opi pet emoji tables

Two generated TSV tables that describe the twelve pet stickers in
[`../stickers/`](../stickers/). The same twelve images are available as plain
PNGs and as animated GIFs in [`../stickers-gif/`](../stickers-gif/).

Everything here is generated by
[`scripts/gen_pet_emoji_table.py`](../../../scripts/gen_pet_emoji_table.py)
from `PetEmojiMap.kt`, `PetMood` in `OpiPet.kt`, and the PNG sources. Do not
edit the generated files by hand.

## Files

| File | Contents |
|------|----------|
| `map.tsv` | `mood`, stable codepoint ID, sticker file, Chinese label, shortcode |
| `shortcodes.tsv` | shortcode, sticker file, Chinese label |
| `README.md` | this file |

The directory name `emoji-font/` is historical. There is **no font here**:
the project no longer ships a PUA/color font, and nothing inserts PUA text
into input fields. The sticker panel uses the animated GIFs / PNGs; when an
editor rejects images the apps insert the `[小欧·笑]` text label instead.

## Bundled in the apps

Builds copy the two tables into Android assets `pet-font/` and the desktop
classpath `/pet-font/`. Android and desktop parse them with the shared
`PetEmojiTable.parseMap` / `parseShortcodes`; a malformed table fails loudly
instead of silently dropping rows. iOS keeps a hand-copied mirror
(`ios/PetEmojiTable.swift`); Harmony has no table copy after the 2026-10-20
font removal.

## Stable IDs

The `codepoint` column is a **stable internal identifier** for each form, in
`PetMood` order (excluding the input-only `SLEEPY` / `DEGRADED` states). It is
not a character the app ever types. The values sit in the BMP Private Use Area
so they cannot collide with real emoji codepoints:

| Mood | ID | Shortcode | File | Label |
|------|----|-----------|------|-------|
| `IDLE` | U+E000 | `:opi_smile:` | `idle.png` | 小欧·笑 |
| `WAITING` | U+E001 | `:opi_joy:` | `waiting.png` | 小欧·欢乐 |
| `PUZZLED` | U+E002 | `:opi_sad:` | `puzzled.png` | 小欧·沮丧 |
| `CRYING` | U+E003 | `:opi_cry:` | `crying.png` | 小欧·哭 |
| `TERRIFIED` | U+E004 | `:opi_scream:` | `terrified.png` | 小欧·惊恐 |
| `ANGRY` | U+E005 | `:opi_angry:` | `angry.png` | 小欧·愤怒 |
| `COQUETTISH` | U+E006 | `:opi_plead:` | `coquettish.png` | 小欧·撒娇 |
| `CUTE` | U+E007 | `:opi_wink:` | `cute.png` | 小欧·卖萌 |
| `PLEASING` | U+E008 | `:opi_pray:` | `pleasing.png` | 小欧·讨好 |
| `KNOCKING` | U+E009 | `:opi_hammer:` | `knocking.png` | 小欧·敲打 |
| `FACE_PALM` | U+E00A | `:opi_facepalm:` | `face-palm.png` | 小欧·捂脸 |
| `TONGUE_OUT` | U+E00B | `:opi_tongue:` | `tongue-out.png` | 小欧·吐舌头 |

New moods may only be appended to `PetMood`; new IDs and shortcodes are
appended after U+E00B. Existing assignments are stable.

The table does **not** map the Unicode smileys from `PetEmojiMap`
(😊 😄 😞 …). Those remain the app's submit-emoji behavior; the pet entries
are images/labels only.

## Shortcodes

`shortcodes.tsv` contains one stable name per sticker, e.g. `:opi_smile:`.
These are **names for clients with custom-emoji support** such as Slack or
Mattermost: the PNG must be uploaded/registered under that name in the
workspace, then typing the shortcode renders the image. The apps do not insert
shortcode text into input boxes.

Shortcode rules:

- one shortcode per sticker file, no duplicates;
- always `:opi_` + a lowercase English word + `:`; names never change once
  published;
- the colon-wrapped form is stored in the files.

## Regenerate and verify

No third-party Python packages are needed.

```sh
python3 scripts/gen_pet_emoji_table.py          # rebuild the TSVs
python3 scripts/gen_pet_emoji_table.py --check  # verify committed files
```

`--check` rebuilds both tables in memory, fails if a committed file differs,
and also checks that `ios/PetEmojiTable.swift` (a hand-copied mirror of the
labels and file names) is still in sync.
