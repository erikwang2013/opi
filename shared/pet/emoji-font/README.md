# Opi pet emoji font

A color OpenType font built from the twelve pet stickers in
[`../stickers/`](../stickers/). The same twelve images are available as plain
PNGs and as animated GIFs in [`../stickers-gif/`](../stickers-gif/); this
directory adds a **color font** and **shortcode** representation.

Everything here is generated by
[`scripts/gen_pet_emoji_font.py`](../../../scripts/gen_pet_emoji_font.py)
from `PetEmojiMap.kt`, `PetMood` in `OpiPet.kt`, and the PNG sources. Do not
edit the generated files by hand.

## Files

| File | Contents |
|------|----------|
| `opi-emoji.ttf` | Color OpenType font, family **Opi Emoji**, 12 private-use glyphs |
| `map.tsv` | `mood`, `codepoint`, sticker file, Chinese label, shortcode |
| `shortcodes.tsv` | shortcode, sticker file, Chinese label |
| `README.md` | this file |

## Bundled in the apps

Builds copy the three generated files into Android assets `pet-font/`, desktop
classpath `/pet-font/`, and the Harmony rawfile directory `pet-font/`. This
repository has no Xcode project, so iOS embeds the same bytes and TSVs in
`ios/PetEmojiFont.swift` and registers family `Opi Emoji` at runtime; Harmony
also has a generated `PetEmojiFont.ets` helper. Android and desktop parse the
tables with the shared `PetEmojiFont.parseMap` / `parseShortcodes`; a malformed
table fails loudly instead of silently dropping rows. The sticker panel does
not depend on the font (it uses the animated GIFs / PNGs). CoreText commonly
supports `sbix`/`COLR`, not the SVG/CBDT tables used here, so iOS registration
may succeed while PUA glyphs render blank; this is a renderer limitation, not
a loading failure.

## Codepoints

The font uses the BMP Private Use Area, one codepoint per mood, in
`PetMood` order (excluding the input-only `SLEEPY` / `DEGRADED` states):

| Mood | Codepoint | Shortcode | File | Label |
|------|-----------|-----------|------|-------|
| `IDLE` | U+E000 | `:opi_smile:` | `idle.png` | 笑 |
| `WAITING` | U+E001 | `:opi_joy:` | `waiting.png` | 欢乐 |
| `PUZZLED` | U+E002 | `:opi_sad:` | `puzzled.png` | 沮丧 |
| `CRYING` | U+E003 | `:opi_cry:` | `crying.png` | 哭 |
| `TERRIFIED` | U+E004 | `:opi_scream:` | `terrified.png` | 惊恐 |
| `ANGRY` | U+E005 | `:opi_angry:` | `angry.png` | 愤怒 |
| `COQUETTISH` | U+E006 | `:opi_plead:` | `coquettish.png` | 撒娇 |
| `CUTE` | U+E007 | `:opi_wink:` | `cute.png` | 卖萌 |
| `PLEASING` | U+E008 | `:opi_pray:` | `pleasing.png` | 讨好 |
| `KNOCKING` | U+E009 | `:opi_hammer:` | `knocking.png` | 敲打 |
| `FACE_PALM` | U+E00A | `:opi_facepalm:` | `face-palm.png` | 捂脸 |
| `TONGUE_OUT` | U+E00B | `:opi_tongue:` | `tongue-out.png` | 吐舌头 |

New moods may only be appended to `PetMood`; accordingly, new codepoints and
shortcodes are appended after U+E00B. Existing assignments are stable.

The font does **not** map the Unicode smileys from `PetEmojiMap`
(😊 😄 😞 …). Those remain the app's submit-emoji behavior; the font only adds
a separate PUA representation of the artwork.

## Font format

`opi-emoji.ttf` is a TrueType-flavored OpenType font (`unitsPerEm` 1000,
ascender 1000, descender 0) with two color representations of each glyph:

- **SVG table**: one self-contained SVG document per glyph, embedding the
  full 280×280 source PNG as a `data:image/png;base64` URI. Coordinates use
  the OT-SVG convention (y-down, baseline at y=0, image occupying
  y = -1000…0).
- **CBDT/CBLC**: one 120 ppem, 32-bit PNG bitmap strike, for renderers that
  support color bitmaps but not OT-SVG (FreeType, Chrome/Chromium, Android).

Both tables are generated here; there are no third-party emoji fonts or
outlines involved. The `glyf` outlines are intentionally empty: renderers
without a usable color table show a blank advance instead of a monochrome
fallback. A `.woff2` is not generated: WOFF2 compression needs the optional
`brotli` package, which is not a dependency of the generator.

### Where it renders

- A system or application must **select this font** for the PUA characters
  (install it and use the family name `Opi Emoji`, or load it with
  `@font-face`). PUA codepoints have no OS-level fallback, so an ordinary
  text field left on the default font will not magically pick them up.
- A renderer must support one of the color tables. Chrome/Chromium does not
  render the OT-SVG table (verified locally: the font loads but the glyph is
  blank), so it falls back to the CBDT strike; the CBDT path is exercised in
  Chrome and FreeType/Pillow.
- The CBDT strike is fixed at 120 ppem. Renderers scale it to the requested
  size; large sizes may look soft. The SVG table scales cleanly where it is
  supported.
- Color-only glyphs are invisible in monochrome-only text stacks.
- This font contains SVG and CBDT/CBLC only. Apple/CoreText targets commonly
  use `sbix` or `COLR`, and Windows DirectWrite support for these tables
  varies; verify rendering on each target platform before shipping there.

Minimal webfont usage:

```html
<style>
  @font-face {
    font-family: "Opi Emoji";
    src: url("opi-emoji.ttf");
  }
  .opi { font-family: "Opi Emoji"; }
</style>
<span class="opi">&#xE000;&#xE001;</span>
```

## Shortcodes

`shortcodes.tsv` contains one stable name per sticker, e.g. `:opi_smile:`.
These are **names for clients with custom-emoji support** such as Slack or
Mattermost: the PNG must be uploaded/registered under that name in the
workspace, then typing the shortcode renders the image. The font does not
implement shortcode ligatures, and a plain app or chat input box will simply
show the text `:opi_smile:`.

Shortcode rules:

- one shortcode per sticker file, no duplicates;
- always `:opi_` + a lowercase English word + `:`; names never change once
  published;
- the colon-wrapped form is stored in the files.

## Regenerate and verify

Dependencies (install once; the generator does not install packages):

```
fontTools==4.63.0
Pillow==12.2.0
```

```sh
python3 scripts/gen_pet_emoji_font.py          # rebuild font + TSVs
python3 scripts/gen_pet_emoji_font.py --check  # verify committed files
```

`--check` rebuilds everything in memory and fails if any committed output
differs. The same run validates the font independently:

- the TTF loads with fontTools; every U+E000…U+E00B cmap entry maps to the
  expected glyph ID;
- each of the 12 SVG documents is well-formed, contains a PNG data URI, and
  the decoded bytes equal the source PNG;
- the CBDT/CBLC tables contain one 120 ppem, 32-bit strike whose image data
  equals the downscaled PNG and whose metrics match the em square;
- the fixed `head.created` / `head.modified` timestamps hold, so repeated
  runs are byte-identical (verified by comparing two builds).

Additional local render check (optional):

```sh
fc-scan shared/pet/emoji-font/opi-emoji.ttf | grep color   # color: True
```
